# ПОСИДИМ — аудит и план внедрения

Дата аудита: 2026-11-18  
Репозиторий: 333cloud/posidim, ветка main

## 1. Текущая архитектура

- Expo SDK 54, React Native 0.81, React 19, TypeScript 5.9, Expo Router.
- Основной интерфейс приложения сосредоточен в `app/index.tsx`.
- Supabase JS 2.x подключён в `lib/supabase.ts`; сессия сохраняется через AsyncStorage.
- Авторизация: email/password, регистрация передаёт display_name, age, city; SQL-триггер проверяет возраст 18+ и создаёт профиль.
- Основные таблицы: profiles, events, event_members, messages, user_blocks, reports.
- Дополнительные миграции: event_invitations.sql и discovery_and_events.sql.
- Загрузка аватарки использует Expo ImagePicker и Supabase Storage bucket `avatars`.
- Карта использует Leaflet, CARTO tiles и Nominatim; на карте сейчас геокодируются встречи, а не точные координаты людей.

## 2. Что уже работает по коду

- Регистрация, вход и восстановление текущей сессии.
- Чтение и изменение базовых полей профиля.
- Загрузка и сохранение URL аватарки (при условии, что bucket `avatars` и Storage policies настроены в Supabase).
- Создание встреч, список встреч по городу, заявки/участие.
- Приглашения на встречи и атомарный ответ через RPC `respond_to_event_invitation`.
- Общий чат встречи через таблицу `messages`.
- Переключатель `is_discoverable`, выдача профилей по городу и сохранение реакции.
- Свайп карточек и создание быстрых предложений о встрече.

## 3. Обнаруженные пробелы и риски

### Приватность и безопасность
- Политика `profiles_read_authenticated` в базовой схеме использует `USING (true)`. Поэтому фильтрация скрытых профилей только на клиенте не является защитой: авторизованный клиент может читать профили напрямую. Нужны серверные политики и контролируемые RPC/представления.
- Нельзя публиковать точные координаты пользователей. Координаты следует хранить отдельно от публичных данных и отдавать только грубо округлённую позицию при разрешённой видимости.
- В базовой схеме есть таблицы `user_blocks` и `reports`, но наличие таблиц не означает наличие полноценного интерфейса, очереди модерации и процессов обработки.
- В проверенных SQL-файлах нет настройки bucket `avatars` и Storage policies. Существующую загрузку необходимо проверить в Supabase Dashboard; не предполагать, что bucket автоматически создан.
- До публичного запуска нужны ограничения частоты действий, проверки входных данных, защита от спама и модераторский процесс.

### Функции продукта
- Нет таблицы галереи профиля и интерфейса нескольких фотографий.
- Нет полного набора публичных полей профиля: статус с истечением срока, интересы, цели знакомства и предпочтения.
- Реакции хранятся в `profile_reactions`, но нет полноценного взаимного match, списка совпадений и надёжного изменения/отмены реакции.
- Нет личных диалогов один на один; текущие `messages` относятся к встречам.
- Нет полноценного радиусного поиска людей по координатам: текущая выдача ограничена совпадением города.
- Нет реального присутствия людей на карте; отображаются геокодированные встречи.
- Нет UI для блокировки и жалоб, несмотря на существующие таблицы.
- Верификация личности, проверка селфи/liveness и модерация изображений не подключены. Нельзя обозначать аккаунт проверенным без реальной процедуры и результата проверки.
- Не обнаружена подписка Realtime для сообщений; текущий чат загружает сообщения запросом к базе при открытии/отправке.
- Интерфейс сейчас имеет четыре основных пункта навигации: «Главная», «Карта», «Чаты», «Профиль». Целевая структура — пять: «Карта», «Симпатии», «Встречи», «Сообщения», «Мой профиль».

## 4. Принципы дальнейшей работы

1. Не переписывать приложение с нуля и не удалять действующие функции.
2. Каждое изменение схемы — отдельная версионированная SQL-миграция; существующие миграции не переписывать.
3. Перед изменением файла получать актуальную версию и SHA из GitHub.
4. После каждой фазы проверять TypeScript, web-сборку и основные пользовательские сценарии.
5. Секретный service_role key не помещать в приложение. Клиент использует только publishable/anon key и RLS.
6. Фото и персональные данные защищать серверными политиками; скрытие в интерфейсе не считается контролем доступа.
7. Верификацию, модерацию и геолокацию включать только после тестов безопасности и явного согласия пользователя.
8. Не обещать бесплатность внешних сервисов без проверки их актуальных тарифов.

## 6. Условия приёмки каждой фазы

- Пользователь может выполнить действие с реального устройства.
- Данные сохраняются в Supabase и остаются после перезапуска/повторного входа.
- RLS и Storage policies проверены под разными аккаунтами.
- Скрытый/заблокированный профиль недоступен через прямой запрос, а не только скрыт визуально.
- Ошибки сети и отказ в разрешении обрабатываются понятно.
- TypeScript и сборка проходят без ошибок.
- Ни одна новая функция не ломает регистрацию, встречи, приглашения и групповые сообщения.

## Обновление 2026-11-19 — базовая защита от спама

- Добавлены серверные ограничения частоты: до 80 реакций в час, до 30 личных сообщений за 5 минут и до 12 приглашений в час на аккаунт.
- Проверки выполняются триггерами PostgreSQL, поэтому их нельзя обойти простым вызовом Supabase API в обход интерфейса.
- Миграция `supabase/anti_spam_limits.sql` включена в `supabase/next_features.sql`.
- Это базовые лимиты, а не полноценная антифрод-система: для публичного запуска нужны мониторинг, защита от мультиаккаунтов и ручная модерация.
- Ограничение сообщений применяется и к групповым чатам встреч: до 30 сообщений за 5 минут на аккаунт.

## Усиление приватности карты

- Смещение точки на карте теперь стабильно для каждого профиля и одинаково для всех смотрящих, чтобы повторные обновления и несколько аккаунтов не позволяли усреднять разные случайные смещения.
- Расстояние, возвращаемое сервером, округляется до 0,5 км; точная дистанция не выдаётся через RPC.

## Карта: центр области поиска

- При включённом геопоиске круг радиуса центрируется на приблизительно округлённой локальной позиции пользователя; после перезапуска приложения позиция восстанавливается из собственной записи.
- В карту передаются округлённые координаты для центра вида, а не точные GPS-координаты.
